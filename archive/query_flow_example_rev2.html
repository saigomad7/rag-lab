전체 흐름

숫자를 묻는 부분과 이유를 묻는 부분이 한 질문에 같이 있습니다. 라우팅이 이를 혼합으로 판정하면 두 경로가 동시에 돌고, 결과를 하나의 컨텍스트로 합쳐 답변합니다.

SELECT YM, SUM(AMT_USD)/NULLIF(SUM(QTY),0) AS 계약가
FROM V_PRICE_MONTHLY
WHERE PRICE_TYPE='CONTRACT'
  AND YM BETWEEN '202607' AND '202609'
  AND PRODUCT_CODE IN ('P-ESSD')
GROUP BY YM ORDER BY YM
FETCH FIRST 200 ROWS ONLY

이 흐름이 성립하려면 세 가지가 먼저 있어야 합니다. ① 지표 정의서 — "계약가격"을 집계식으로 옮길 수 있어야 SQL이 나옵니다(S22). ② 문서 날짜 메타 — 같은 기간으로 문서를 거를 수 있어야 이유가 그 분기의 것이 됩니다(S05). ③ 권한 — 두 경로에 같은 사용자 권한이 걸려야 합니다(S28).

A-5. 한 줄 정의, 이렇게 씁니다

좋은 예
계약가격 = 월 단위 확정 계약 단가의 가중평균
SUM(AMT_USD)/NULLIF(SUM(QTY),0) · PRICE_TYPE='CONTRACT' · 단위 USD/GB · 월
→ 계산식 · 대상 · 조건 · 단위가 모두 한 줄에
나쁜 예
계약가격 = 고객과 계약한 가격
→ 단순평균인지 가중평균인지, 현물가 포함인지, 단위가 USD/GB 인지 USD/TB 인지 알 수 없음. SQL 로 옮길 수 없으니 카탈로그에 넣은 의미가 없음

A-6. 자주 빠뜨리는 것

빠뜨리는 것증상대응
기본 필터취소 · 반품 · 테스트 건이 섞여 수치가 조금씩 큼지표마다 "무엇을 제외하는지" 한 줄
단위EB 와 TB, USD/GB 와 USD/TB 가 섞여 1000배 오차단위 칸 필수 · 답변에도 단위 표기
기간 기준"3분기"가 회계연도인지 달력인지 사람마다 다름카탈로그에 기간 표준 한 줄 고정
별칭현업이 부르는 이름으로 물으면 라우팅이 비정형으로 샘실제 질문 20개에서 쓰인 표현을 그대로 별칭에
유사 지표 구분"가격"이 계약가인지 현물가인지 모호별칭을 겹치지 않게 · 모호하면 되묻기
소유 부서수치가 이상할 때 물어볼 사람이 없음지표마다 담당 부서 · 갱신 주기

A-7. 채우는 순서 (한 번에 다 하지 않습니다)

  • 1주차 — 테이블카탈로그: 연계 대상 뷰 5~10개만 고릅니다. 전부 열지 않습니다
  • 1주차 — allow_list: 그 뷰의 허용 컬럼과 제외 컬럼(고객 실명 등)을 정합니다
  • 2주차 — 지표정의: 실제 질문 20개에 나온 지표부터 5~10개. 집계식 · 기본 필터 · 단위는 반드시
  • 2주차 — 코드값사전: 그 지표에 걸리는 제품 · 고객 · 지역 코드와 별칭
  • 3주차 — nb07 로 확인: 라우팅이 맞게 갈라지는지, SQL 이 나오는지, 차단이 도는지
  • 완료 기준 — 실제 질문 20개 중 정형 질문이 카탈로그만으로 SQL 이 되는 비율을 적습니다. 이 비율이 Phase 3 의 출발 점수입니다
한 줄 요약 — 지표 정의서는 문서가 아니라 코드의 입력입니다. "이 칸을 비워 두면 SQL 의 어느 부분이 사라지는가"를 기준으로 채우면 됩니다. 채운 파일은 rag_lab/catalog/metric_catalog.xlsx 로 저장하면 nb07 이 그대로 읽습니다.
